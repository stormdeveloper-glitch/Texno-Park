## 3. CRITICAL #2 — `NaN` butun tizimni jim o'chirib qo'yadi

### Sabab

`validate_sync_payload()` — [app.py:3535-3656](app.py#L3535-L3656) — **`products`** maydonlarini son jihatdan tekshiradi (`math.isfinite`, [app.py:3571](app.py#L3571)), lekin **`sales` (savdo) yozuvlarini umuman tekshirmaydi** (faqat fiskal maydonlarni o'chiradi, [app.py:3651-3654](app.py#L3651-L3654)). Python'ning `json` moduli standart holatda `NaN` va `Infinity` ni **qabul qiladi**, `json.dumps` esa ularni **JSON standartiga zid** bo'lgan `NaN` ko'rinishida yozib qo'yadi.

### Jonli dalil

```
POST /api/sync {"sales":[{"id":777,"total":NaN,"date":"13.10.2026","items":[]}]}
→ HTTP 200 {"savedKeys":["sales"]}

GET /api/data
→ HTTP 200, 6584 bayt, javob ichida "NaN" bor
```

Brauzer tomoni (Node bilan tekshirildi):
```
JSON.parse('{"a":NaN}') → SyntaxError: Unexpected token 'N', "{"a":NaN}" is not valid JSON
```

`Response.json()` aynan `JSON.parse` ni ishlatadi → **istalgan brauzerda parsing yiqiladi**. Frontend esa xatoni **jimgina yutadi** — [scripts.js:1746](scripts.js#L1746) (`await response.json()`) va [scripts.js:1832-1836](scripts.js#L1832-L1836):

```javascript
} catch (e) {
    productLoadState = products.length ? 'ready' : 'error';
    renderProducts();
    console.warn('Failed to load from backend. Using local storage:', e);   // ← jim
}
```

### Oqibat

Ilova “server onlayn” bo'la turib **eski localStorage nusxasini** ko'rsatadi: kassir eski narx/qoldiq bilan savdo qiladi, boshliq eski hisobotni ko'radi. Bundan tashqari `catalogFallbackActive` o'chirilmagani uchun keyingi sinxronizatsiya **eski (xato) holatni serverga qayta yozishi** mumkin.

### Tuzatish

1. `validate_sync_payload()` da **har bir savdo yozuvini** ham tekshirish (`total`, `discAmt`, `items[].price/qty/cost` — `math.isfinite`, manfiy emas) — bu 4-topilmani ham yopadi.
2. Himoya qatlami: `app.json.dumps` ni `allow_nan=False` bilan sozlash (`app.json.compact=...` bilan bir joyda) — shunda xato yozuv **500 bilan rad etiladi**, baza buzilmaydi:
   ```python
   from flask.json.provider import DefaultJSONProvider
   class StrictJSON(DefaultJSONProvider):
       def dumps(self, obj, **kwargs):
           kwargs.setdefault('allow_nan', False)
           return super().dumps(obj, **kwargs)
   app.json = StrictJSON(app)
   ```
3. `db_manager.get_all()` ichida `json.loads` ni himoyalash (buzilgan yozuv butun snapshot'ni yiqitmasin).
4. Frontendda `response.json()` uchun aniq `try/catch` + foydalanuvchiga ko'rinadigan xato (jim `console.warn` emas).

## 4. HIGH #3 — Ommaviy vitrinada saqlangan XSS

### Joy

[scripts.js:3912](scripts.js#L3912) — `renderUzumRecommendations()` (mehmon ham ko'radigan Uzum-uslubidagi vitrina):

```javascript
onclick="(event||window.event).stopPropagation(); addToShopCart(${p.id}); showNotif('success', 'Savatga qo\\'shildi', '${escapeHTML(p.name)}')"
```

`escapeHTML()` `'` belgisini `&#39;` ga aylantiradi ([scripts.js:73](scripts.js#L73)). **Lekin bu atribut ichida ishlamaydi:** brauzer avval HTML obyektini dekodlaydi, keyin JS sifatida kompilyatsiya qiladi — ya'ni `&#39;` yana `'` bo'ladi va JS satridan chiqib ketadi. Bu klassik “kontekstga mos bo'lmagan escaping” xatosi.

### Jonli dalil (brauzer, mehmon sifatida)

1. Mahsulot nomi sifatida XSS payload bazaga yozildi (oddiy `POST /api/sync`):
   ```
   name = X');window.__XSS=1;//
   ```
   Server uni **rad etmadi** (nom uchun faqat uzunlik tekshiriladi: 1–120 belgi).
2. `GET /api/catalog` (autentifikatsiyasiz, mehmon) uni qaytardi:
   ```json
   {"products":[{"cat":"Aksessuarlar","id":1,"name":"X');window.__XSS=1;//","price":1500000.0,"stock":5}]}
   ```
3. Brauzerda DOM'ga tushgan atribut:
   ```
   onclick="...showNotif('success', 'Savatga qo\'shildi', 'X');window.__XSS=1;//')"
   ```
4. “Savatga qo'shish” tugmasi bosilgach:
   ```
   { "xss": 1, "clickError": null }     ← payload bajarildi
   ```

### Ta'sir doirasi

- Hujum **mehmonga ham** ishlaydi (autentifikatsiya kerak emas) — vitrina ochiq.
- Xodim sessiyasida ishga tushsa: token `sessionStorage` da ([scripts.js:1445-1448](scripts.js#L1445-L1448)) → uni o'qib tashqariga yuborish = **akount egallash**; API orqali istalgan amalni bajarish.
- Inject qilish uchun yo'l: admin mahsulot formasi **yoki** kassir tokeni bilan `/api/sync` (4-topilma).
- Xuddi shu naqsh yana **11 joyda** bor — `escapeHTML(...)` bitta-qo'shtirnoqli `onclick="..."` ichida, shu jumladan filial ID ([scripts.js:10266-10272](scripts.js#L10266-L10272)), chegirma ID ([scripts.js:9509-9510](scripts.js#L9509-L9510)), sessiya `jti` ([scripts.js:7037](scripts.js#L7037)). Bu qiymatlar ham `/api/sync` orqali yoziladi (`branchId` — faqat uzunlik cheklangan).

### Tuzatish

1. **Inline `onclick` ichida foydalanuvchi matnini umuman ishlatmaslik.** Eng to'g'ri yechim: `data-*` atributi + bitta delegatsiya qilingan listener, yoki `textContent` orqali yozish.
2. Majburiy bo'lsa: JS-satr kontekstida HTML-entity emas, **`JSON.stringify()`** (yoki alohida `jsStr()` yordamchisi `\` va `'` ni escape qiladigan) ishlatilsin; atribut esa ikki qo'shtirnoq bilan emas, xavfsiz tarzda qurilsin.
3. Serverda nominal maydonlarga **belgilar allowlist** qo'yish (nom/kategoriya/id uchun `<`, `'`, `"`, `(`, `)` ni rad etish yoki sanitizatsiya) — 2-qavatli himoya.
4. CSP'ni kuchaytirish: `script-src` da `'unsafe-inline'` bo'lmasa, bu turdagi XSS umuman bajarilmaydi (hozir inline handlerlar ishlashi uchun ruxsat berilgan bo'lishi ehtimoli yuqori).

## 7. HIGH #6 — Xodim parollari ochiq matnda ko'rinadi
